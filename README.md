# FraudScope — Layer 1: Transaction Detection Engine

Layer 1 of **FraudScope**, an end-to-end fraud intelligence platform.

> **Layer 1 answers:** *Is this transaction suspicious, how risky is it, and why?*

This repository is deliberately focused on the first layer only. It provides a clean, reusable transaction-risk engine that will later feed Layer 2 (fraud-network intelligence) and Layer 3 (AI investigation).

## What is included

- Leakage-safe chronological train/validation/test split
- Strong tabular baseline: Logistic Regression + XGBoost
- Unsupervised anomaly detector: Isolation Forest
- Leakage-safe temporal behavioral features when identifiers are available
- PR-AUC / Average Precision as a primary metric
- Threshold optimization on validation data only
- Cost-aware decision thresholding
- Investigation-capacity evaluation (top 0.1%, 0.5%, 1%, 2% alerts)
- Probability calibration
- SHAP explanations when available
- Single-transaction scoring API
- Streamlit dashboard
- Reproducible CLI training/evaluation

## Dataset

The original project uses the **ULB Credit Card Fraud Detection** dataset: 284,807 transactions, 492 fraud cases, with `Time`, `Amount`, `V1`–`V28`, and `Class`. The existing project already uses a chronological split; this Layer 1 keeps that principle and adds a validation set for model/threshold selection.

Place the official `creditcard.csv` at:

```text
data/raw/creditcard.csv
```

A small synthetic `creditcard_sample.csv` is included only to smoke-test the pipeline. It is NOT the real benchmark dataset and must not be used for reported results.

The official benchmark CSV is not redistributed here; download it from Kaggle using `scripts_download_dataset.py` after configuring Kaggle credentials.

## Pipeline

```text
Raw CSV
  ↓
Validation + chronological sorting
  ↓
70 / 15 / 15 chronological split
  ↓
Leakage-safe preprocessing
  ↓
Behavioral features (if entity/time fields permit)
  ↓
┌────────────────┬──────────────────┐
│ Logistic Reg.  │ XGBoost          │
│ baseline       │ primary model    │
└────────────────┴──────────────────┘
             +
       Isolation Forest
             ↓
Probability / anomaly score
             ↓
Validation-set threshold selection
             ↓
Risk score + LOW/MEDIUM/HIGH/CRITICAL
             ↓
Explanation + operational metrics
```

## Important methodology rules

1. Never tune thresholds on the final test set.
2. Never compute rolling features using future observations.
3. Do not oversample the final test set.
4. Do not report accuracy as the primary metric for this extreme imbalance problem.
5. Keep the original test distribution intact.
6. Never invent entity relationships for future graph layers.
7. Save the exact configuration used for each experiment.
